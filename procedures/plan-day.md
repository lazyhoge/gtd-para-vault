# 日次の計画

本人が「今日の計画」「予定を組んで」「組み直して」と頼んだときに使う。**エージェントが案を出し、
本人が承認したものだけを書く。**

- 時刻まで割り付ける（時間ブロック）。ブロックの終わりは `scheduled` + `estimate` で表し、項目は足さない
- 予定は1タスク1ブロック。実績はタスク側（`intervals`）だけに持ち、予定の側には書かない
- 案を出すのは、前回の片付け（1）が済んでから。古い状態の上に予定を組まない

## 1. 前回の片付け

1. **開きっぱなしの `start`**: `start` が入っているタスクを挙げ、今も作業中か、いつ止めたかを本人に聞く。
   止めた時刻で区間を閉じる（[[record-actuals]]）。時刻が分からなければ、本人の見立てで閉じて
   `annotations` に「止めた時刻は本人の見立て」と残す
2. **繰り返しの回を作る**: 生成スクリプトを流し、出力を daily のログに写す。毎朝 4:00 の定時実行
   （`procedures/recur-daily.sh`）が作っているので、ふつうは何も出ない
   ```
   nix shell nixpkgs#yq-go nixpkgs#jq nixpkgs#taskwarrior3 -c bash ~/vault/procedures/generate-recurring.sh
   ```
3. **過ぎた繰り返しの回**: `parent` を持つ `pending` の回のうち、`scheduled`（無ければ `due`）が今より前のもの。
   **本人に聞かずに、すべて `status: deleted` にする**（判断を増やさないため。本人が選んだ）。前の日までの分は
   毎朝の定時実行が同じ規則で削除しているので、ここで残っているのはふつう今日の分だけ
   - `end` を今にし、`annotations` に「完了の申告が無いまま予定を過ぎた（日次の計画で削除）」と残す
   - やった回を残したいときは、本人がその場で「やった」と言う。その回だけ [[record-actuals]] で完了にする
   - 終わったら生成スクリプトをもう一度流し、親の `mask` を直す
4. **過ぎた予定**: 繰り返しでない `pending` のタスクで、予定のブロック（`scheduled` から `estimate` 分）が
   今より前に終わっているもの。付け替えの候補として 3 に回す

## 2. 材料を集める

1. **使える時間帯**: 今日の残りで作業に使える時間帯と場所（家・会社・外出）、決まっている予定を本人に聞く。
   カレンダーはまだ読めない（未実装）。前回の計画で使った時間帯を、
   選択肢の先頭に出す（daily のログから引く）

2 と 3 は `procedures/vault-query.sh tasks` の出力から拾う（`scheduled`・`due`・`tags`・`start` が1行に出る）。

2. **動かさないブロック**: 今日の `scheduled` を持つ `pending` のタスク（繰り返しの回を含む）。時刻は動かさない
3. **候補**: 次のどれかに当たる `pending` のタスク
   - `next` が付いている（`waiting` は除く）
   - `due` が7日以内か、過ぎている
   - 1-4 の過ぎた予定

   次のものは外す: `wait` が未来のもの、未完了の `depends` が残っているもの、状況タグ（`computer` /
   `home` / `errands` など）が今日の場所と合わないもの
4. **並べる順**: 緊急度（Taskwarrior の既定の係数で計算した値が正本。`views/next-actions.base` の式は表示用の写し）の高い順。手で計算せず、
   使い捨ての Taskwarrior に全タスクを入れて `task export` の `urgency` を読む（生成スクリプトと同じ方式。
   一時ディレクトリは最後に消す）
5. **長さ**: `estimate` から `actual` を引いた残り。`estimate` が無ければ、見積もりの案を付けて本人に確かめる

## 3. 案を出す

空いた時間帯に、緊急度の高い順に詰める。

- 残りの長さが入る空きが無いタスクは、途中まで入れない。入る空きが無ければ「入らなかった候補」に回し、
  分けるなら Project への格上げを提案する（規約の「分解」）
- 冒頭に「今日は何を優先するか」を1文で書き、続けて表を出す

| 時刻 | タスク | 長さ | 緊急度 | 理由（1行） |
|---|---|---|---|---|
| 16:00 | ストレッチ（繰り返しの回。動かさない） | 5 | | 繰り返し |
| 16:10 | （タスクへのリンク） | 30 | 29.7 | 止めている数 2 |

- 表の下に、入らなかった候補を1行ずつ（理由つき）
- 前回の計画との差（付け替えたもの・外したもの）があれば、それも書く

## 4. 承認と書き込み

本人が行ごとに採る・直す・捨てるを決める。**採ったものだけを書く。**

- `scheduled` に開始時刻を書き、`modified` を今にする
- すでに `scheduled` があるタスクを動かすときは、元の予定を `annotations` に残す
  （`{ entry: <今>, description: "予定を 2026-10-01T19:00:00 から 2026-10-02T09:00:00 に付け替えた（理由）" }`）
- daily のログに1行で残す（「HH:mm 日次の計画: [[a]] 13:00・[[b]] 14:00 を予定に入れた（本人が承認、エージェントが対応）」）。
  使った時間帯もここに書く（次の計画で 2-1 の選択肢に使う）

## 5. 途中で組み直す

中断や割り込みのあとに「組み直して」と言われたら、1-1 から始めて、今からの残りの時間で 2〜4 をやり直す。

- 中断で残った分は、同じタスクの `scheduled` を次のブロックに付け替える（予定は1タスク1ブロック。
  元の予定は `annotations` へ）
- 1-2・1-3 は前回の計画から日付が変わっていなければ飛ばしてよい
